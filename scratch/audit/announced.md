# announced

## SUMMARY
The announced social contract (group chat, HOW-TO-PLAY, Fabian's admin package, README, and the in-app Rules page) matches the code on the headline numbers — exact 10 / outcome 2 / scorer 8 / first-team 2 / booster ×2 / payout 60-30-10 — but diverges on four fairness-critical points. (1) The tiebreaker is announced as "Earliest pick submission … Decisiveness pays," while the code breaks ties by the LATEST edit timestamp across ALL of an entry's picks (ascending), and every save — even re-saving an unchanged pick — refreshes that timestamp; meanwhile three separate pieces of copy promise "edit as often as you like until kickoff," so ordinary editing silently destroys tiebreak position in a pool where ties at a ~$600 payout boundary are plausible. (2) The +5 underdog bonus is advertised unconditionally in every scoring table, but autoUnderdogEnabled defaults to 0 and no-flag = no-bonus, while Fabian is told "most days you do nothing" — the bonus is almost certainly inert, and arming it mid-tournament applies the rule unequally across matchdays. (3) setUnderdog has no kickoff/finished guard: the playing admin (who runs a second player account) can flag an underdog AFTER full-time, with everyone's picks visible, and recompute hands out +5 (×2 boosted = 10+) retroactively — contradicting both the README ("before a match") and the auto-mode promise ("the flag freezes at kickoff"). (4) Any admin change to points/booster/round multipliers retroactively re-scores every finished match with no audit trail, and the Rules page silently regenerates — Fabian was handed "knockout round multipliers" as a knob while players' Rules page currently promises "Every round counts the same in this league." Announced tone is jokey trash-talk ("Last place gets the red card… Don't be that guy"), which means rule clarifications announced openly in chat will land fine, but silent retroactive recomputes would breach the social contract badly.

Mismatch needs either copy fix or mechanism change (e.g. per-tied-match earliest createdAt) — mid-tournament, copy fix plus group-chat announcement is the only fair option.

- [high/high] Any settings tweak retroactively rewrites all past scores with no audit trail, while the announced rule sheet silently mutates to match

  updateLeagueSettings runs recomputeLeague over every finished match whenever points values, boosterMultiplier, or roundMultipliers change; the Rules page is generated live from settings (README: "auto-generated from your settings"), so after a change there is no in-app record that the rules were ever different — history is re-priced and the contract self-edits. Specific landmine: Fabian's package hands him "knockout round multipliers" as a normal knob while the players' Rules page currently promises "Every round counts the same in this league" — if he arms ×2 knockouts in July, the title and the $600 are decided under rules nobody agreed to (and a recompute re-prices any already-finished knockout matches). Mitigation that fits the announced culture: announce any change in the group chat before saving, and only apply changes forward (the app cannot do forward-only — that is the gap).
- [low/high] 'Pure bonus — it can never hurt you' is settings-dependent: booster accepts 0<×<1 and stage/point values accept 0

  The booster promise ("can never hurt you" / "pure upside") holds only because the default is 2: the API accepts any boosterMultiplier in (0,100], so 0.5 would make boosted matches score HALF — and a recompute would retroactively halve past boosted wins. validateNumberRecord allows 0 for scoring values and round multipliers, so a fat-fingered 0 on "final" or on "exact" zeroes a whole stage/category retroactively. No second-confirm in the admin form beyond ">0" checks. Pure admin-misconfig risk (non-technical admin, mobile form), not player-exploitable.
- [low/high] Undisclosed 5th tiebreaker: lower entryId (earlier joiner) wins a dead-even tie
  evidence: src/lib/services/leaderboard.ts:52-55; src/app/league/[slug]/rules/page.tsx:197-207
  The Rules page lists exactly four tiebreak levels; the code falls through to entryId ASC when totals, exacts, scorer hits, AND lastPickAt all match — i.e. whoever tapped the invite link first wins money on a perfect tie. Probability is low (lastPickAt has ms resolution), but if it ever fires at a payout boundary it is an unannounced coin-flip favoring early joiners. One sentence on the Rules page fixes it.
- [low/medium] Pot math counts entries, not people — entriesPerUser can be raised to 10 mid-tournament
  evidence: src/app/api/leagues/[slug]/settings/route.ts:41; CONTRACTS.md:133-136; HOW-TO-PLAY.png; FABIAN-ADMIN-PACKAGE.txt:27-28

The admin can raise entriesPerUser (1..10) any time; extra entries dilute payout odds for everyone else and let one player buy multiple lottery tickets — late extra entries also start with 0 points but still count toward the displayed pot (buyInCents × entryCount), inflating the advertised pool with money that may never be collected on Venmo. Display-only money limits the blast radius, but it is a group-chat-argument generator.
